# 🎯 Finvanta Health Prototype — Demonstration Checklist

**Quick-start guide for your first stakeholder demonstration**

---

## ⏰ 15 Minutes Before Demo

### Technical Preparation
- [ ] Open application URL in browser
- [ ] Test password works (if using password-protected deployment)
- [ ] Load all three scenarios (low, moderate, high) to verify they work
- [ ] Close unnecessary browser tabs
- [ ] Increase browser zoom to 110-125% for better visibility on shared screen
- [ ] Enable "Do Not Disturb" mode (silence notifications)
- [ ] Check internet connection stability

### Materials Preparation
- [ ] Have demonstration script ready (see below)
- [ ] Prepare 3-5 questions to ask stakeholders
- [ ] Have note-taking method ready (document, notebook)
- [ ] Know your audience (names, roles, organizations)

## 🎬 Demo Script (25 minutes total)

### 1. Opening & Context Setting (3 minutes)

**Key points to cover:**
- "This is a prototype diagnostic tool using 100% synthetic data"
- "Goal: Help identify bottlenecks in mental health benefit implementation"
- "We're seeking feedback on whether this type of analysis is useful"

**Script example:**
> "Thanks for taking time to review this prototype. What you're seeing is the Finvanta Health Benefit Diagnostic tool - a visualization system that helps identify where mental health benefit implementation is getting stuck. All data you'll see today is completely synthetic, created to demonstrate how the tool would work with real PhilHealth data. Our goal today is to get your feedback on whether this type of analysis would be useful for resource allocation and policy decisions."

### 2. Scenario Overview (2 minutes)

**Show:** Scenario selector dropdown

**Key points:**
- "Three scenarios: low, moderate, high implementation activity"
- "Each represents different levels of facility accreditation and claims processing"
- "Let's start with the moderate scenario - most representative of current state"

**Script example:**
> "We've modeled three implementation scenarios. The 'moderate' scenario assumes 15% of facilities get accredited and about 600 claims per quarter - this roughly matches what we've seen in early rollouts. The 'low' and 'high' scenarios show what happens with much less or much more engagement."

### 3. Executive Overview Walkthrough (5 minutes)

**Show:** Executive Overview section (top cards)

**Key metrics to highlight:**
- Facilities that submitted applications vs. got accredited
- Patients who registered vs. actually received treatment
- Claims submitted vs. successfully processed
- Overall bottleneck severity (red/yellow/green indicators)

**Key questions to pose:**
- "Does this match how you think about implementation stages?"
- "Are these the right milestones to track?"

**Script example:**
> "This top section shows where we're losing participation at each stage. In this moderate scenario, 800 facilities applied for accreditation, but only 120 completed it - that's an 85% drop-off. Similarly, 4,800 patients registered, but only 575 received treatment. These drop-offs help us identify where to focus support resources."

### 4. Facility Cascade Deep Dive (8 minutes)

**Show:** Facility Participation Cascade (waterfall chart)

**Key insights:**
- Visual drop-offs at each implementation stage
- Comparison between "All Facilities" and "Psychosocial Services Capable"
- Bottleneck severity indicators (color-coded)

**Key questions to pose:**
- "Which drop-off surprises you most?"
- "Would you prioritize differently if you saw this breakdown?"
- "What contextual factors might explain these patterns?"

**Script example:**
> "This cascade shows exactly where facilities are dropping out. The biggest drop is from application to accreditation - we lose 85% of facilities here. What's interesting is that psychosocial-capable facilities have slightly better rates, but still face major barriers. The red indicator here suggests accreditation itself is a critical bottleneck - maybe documentation requirements, training gaps, or administrative burden."

### 5. Claims Processing Cascade (5 minutes)

**Show:** Claims Processing Performance section

**Key insights:**
- Patient registration through treatment completion
- Claims submission through reimbursement
- Time delays and administrative burden

**Key questions to pose:**
- "Does the claims timeline match your experience?"
- "Are the identified bottlenecks consistent with feedback you've heard?"

**Script example:**
> "On the claims side, we see patients who make it through registration but never receive treatment - possibly due to facility capacity constraints or patient-side barriers like transportation or stigma. Then we see submitted claims that get rejected, often due to documentation issues. Would addressing one of these bottlenecks have more impact than the other?"

### 6. Recommendations & Insights (5 minutes)

**Show:** Diagnostic Insights section (bottom of page)

**Key insights:**
- Top 3 bottlenecks identified
- Preliminary recommendations (always tentative)
- Potential interventions

**Key questions to pose:**
- "Do these recommendations align with strategies you're already considering?"
- "What's missing that would make these more actionable?"
- "Would you want this analysis for specific regions or facility types?"

**Script example:**
> "Based on the cascade analysis, the tool suggests three priority areas: streamlining accreditation, boosting patient engagement, and improving claims documentation support. These are preliminary recommendations - the tool isn't claiming causality, just identifying where the biggest drop-offs occur. Would insights like this change how you allocate technical assistance resources?"

### 7. Q&A and Feedback Collection (15 minutes)

**Key questions to ask:**

**Clarity & Comprehension:**
- "Was the bottleneck analysis clear and easy to understand?"
- "Did any visualizations confuse you?"
- "What would you change about how information is presented?"

**Usefulness & Relevance:**
- "Would this type of analysis be useful for your work?"
- "How would you use these insights in decision-making?"
- "What's the most valuable insight you got from this?"

**Accuracy & Validity:**
- "Do the identified bottlenecks match your experience?"
- "Are there implementation barriers this analysis is missing?"
- "Would you trust this analysis enough to act on it?"

**Feature Requests:**
- "What additional filters or breakdowns would you want?" (by region, facility type, time period)
- "What other metrics would be useful to track?"
- "Would you want to compare scenarios side-by-side?"

## 🚫 Common Pitfalls to Avoid

### ❌ Don't Oversell
- This is a prototype, not a finished product
- Recommendations are preliminary, not prescriptive
- Tool identifies patterns, doesn't establish causality

### ❌ Don't Rush Through Scenarios
- Let stakeholders absorb visualizations (15-20 seconds pause after showing new chart)
- Ask "What do you notice?" instead of immediately explaining
- Allow stakeholders to ask questions mid-demo

### ❌ Don't Ignore Negative Feedback
- If someone finds it confusing, dig deeper (what specifically?)
- If they're skeptical, understand why (data quality concerns? methodology?)
- Negative feedback is often the most valuable for iteration

### ❌ Don't Forget the "Why"
- Always tie insights back to real-world decisions
- Connect bottlenecks to potential interventions
- Frame in terms of resource allocation and impact

## ✅ Post-Demo Checklist

### Immediate Follow-Up (Within 24 hours)
- [ ] Transcribe notes while fresh in memory
- [ ] Send thank-you email to stakeholder
- [ ] Share password-protected URL if they want to explore further
- [ ] Add key feedback to tracking document

### Synthesis (After 3-5 demos)
- [ ] Identify common themes across stakeholders
- [ ] Prioritize design improvements based on frequency/severity
- [ ] Decide whether to proceed to Stage 2 validation
- [ ] Update demo script based on what resonated most

### Decision Point (After Stage 1 Complete)
**Criteria for proceeding to Stage 2:**
- ✅ At least 60% of stakeholders found it useful
- ✅ No major conceptual misunderstandings identified
- ✅ Identified bottlenecks resonate with stakeholder experience
- ✅ Clear demand for deeper validation

## 🎯 Success Metrics for First Demo

**Minimum success criteria:**
- [ ] Stakeholder understood the purpose (diagnostic tool for implementation bottlenecks)
- [ ] No major technical issues (application loaded, scenarios worked)
- [ ] Generated at least one substantive conversation about implementation challenges
- [ ] Received specific feedback (not just "looks good")

**Ideal success criteria:**
- [ ] Stakeholder expressed interest in using it for their work
- [ ] Identified at least one insight they hadn't considered before
- [ ] Asked specific questions about methodology or data sources
- [ ] Requested features or enhancements for future iterations
- [ ] Offered to connect you with other relevant stakeholders

## 📊 Sample Questions by Stakeholder Type

### For PhilHealth Program Officers:
- "Does this match the implementation patterns you've seen in other benefit programs?"
- "Would this type of analysis help prioritize technical assistance resources?"
- "What regional variations would be important to show?"

### For Facility Administrators:
- "Do the identified accreditation bottlenecks match your experience?"
- "What facility characteristics would be useful filters?" (bed count, location, ownership)
- "Would your facility find value in seeing its performance relative to this benchmark?"

### For Policy Analysts:
- "What additional contextual factors would strengthen this analysis?"
- "How would you validate these bottleneck identifications?"
- "What policy levers would you test against this diagnostic framework?"

### For Implementation Partners (NGOs, Technical Assistance):
- "Does this help target where to deploy support resources?"
- "What implementation support interventions would you test based on these insights?"
- "Would comparing facilities that succeeded vs. struggled be valuable?"
